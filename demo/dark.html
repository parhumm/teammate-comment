Notes / Anchoring

Finding the same text twice

A durable reference to a span of text in a document that will not hold still.

The problem looks trivial until you try it. You have a selection now, and you want to find the same words later, in a document that has been edited, re-rendered, translated by a framework, or reordered by a layout change. Character offsets alone will not survive any of that. Neither will a CSS selector, which breaks the moment a wrapper element appears.

Flatten first

Every workable approach starts by flattening the document to a single string of visible text, along with a map back to the nodes that produced each region. Once you are working in offset space, the rest of the problem becomes arithmetic rather than tree traversal.

const walker = document.createTreeWalker(root, NodeFilter.SHOW_TEXT)
let text = '', nodes = []
for (let n; (n = walker.nextNode()); ) {
  nodes.push({ node: n, start: text.length })
  text += n.nodeValue
}

Skip script, style, and anything belonging to your own interface. A tool that annotates its own chrome is a tool that has lost track of what the document is.

The resolution ladder

Store the quote, a hundred characters either side of it, and the offsets. On the way back, try each rung in order and stop at the first that holds:

  1. The stored offsets still contain exactly the stored quote. Nothing moved.
  2. The quote is findable between its stored neighbours. Something moved, but the neighbourhood survived.
  3. The quote appears somewhere, once. Take it.
  4. The quote appears several times. Take the occurrence nearest the original offset.
  5. Nothing matches. The anchor is orphaned.

Nothing edited1

Orphans are a state, not an error

The last rung is the one most implementations get wrong, usually by silently dropping the anchor. But a conversation attached to deleted text still happened, and the people in it still need to see it and close it out. An orphan belongs in the interface, labelled and reachable, not in a log file.

The temptation at this point is to add fuzzy matching and recover a few more cases. It is worth resisting. Similarity scoring buys a handful of recoveries in exchange for behaviour nobody can predict, and a highlight landing confidently on the wrong sentence is a worse outcome than an orphan the reader can see and judge for themselves.
