Websites, blogs, docs and HTML reports

If it opens in a browser and you can add a script tag to it, your team can comment on it.

  • Websites before launchClients and teammates mark up the copy on the staging site itself, instead of in screenshots, email chains or a spreadsheet of URLs.
  • Blog posts and articlesEditors comment on a draft line by line, as they would in a Google Doc, but in the real layout with the real images.
  • HTML reportsResearch, analytics, audit and AI-generated reports. Readers question the exact sentence or number, and the answer stays next to it.
  • Documentation and help centersSupport and product flag the step that is out of date, right where readers get stuck on it.
  • Prototypes and AI-built pagesComment on a page an assistant generated, then copy the threads as Markdown and paste them back so it makes the edits.
  • Proposals and client deliverablesSend a link instead of a PDF and collect sign-off in threads that get resolved, not lost in an inbox.

One string to copy

No npm package, no build step, no server-side install, no framework. The project key rides in the script URL, so there is one string to copy and nothing to mis-wire.

The bundle is byte-identical for every project and revalidates on each load, so a fix you ship reaches every page that carries it without anyone re-pasting anything.

Paste before </body>
<script src="https://teammate.jaan.to/w/PROJECT_KEY.js"></script>
The only option
<script src="https://teammate.jaan.to/w/PROJECT_KEY.js" data-theme="dark"></script>

light or dark. Without it the widget reads the host page's color-scheme, then the colour of its body text, then the reader's prefers-color-scheme. Only the chrome inverts; hue, spacing, type and shape stay put.

How it works

Owners sign up once and hand over a snippet. Commenters never have an account and never meet a signup screen. They open a page and start marking it up.

Built for private review with people you trust. Anyone who can open the page can read and comment. Only you resolve, edit and delete, on the page through a private owner link or straight from your dashboard.

Owners

  1. Sign up once. One account holds every project you install.
  2. Create a project per site and name the domain it may run on.
  3. Paste the snippet before </body>. That is the whole install.
  4. Answer from the dashboard. Every thread, per project and per page, to reply, resolve, reopen, delete or copy.

Commenters

  1. Open the page. A staging site, a blog draft, an HTML report.
  2. Select the text the feedback is about.
  3. Comment and reply. Your name is asked once and kept on your device. Email is optional and only the owner sees it.

Nothing to learn

No tour, no tooltips, no coach marks. Selecting text to comment is one gesture, and everything else follows from it.

Select text
A Comment pill appears at the end of the selection. On a touchscreen it waits at the bottom of the screen, clear of the system's copy menu.
C with text selected
The same thing without the mouse. Ignored while you are typing in a field.
Click a highlight
Opens its thread. Where highlights overlap, the smallest range wins, because it is the most specific thing you could have meant.
💬 launcher
Opens the sidebar: every thread on the page in document order, open ones counted on the badge.
Esc
Closes the composer or the open thread, then leaves select mode, then closes the sidebar.
#tc-<id> in the URL
Opens that thread and scrolls to it on load. Comments belong to a page, so ?utm_source=x lands on the same threads as the bare URL.

Hand the feedback to your AI assistant

Copy turns threads into Markdown: the page URL, a CSS path to the element each quote sits in, the quote, and every comment in order. Take one thread, pick a few in the sidebar, or copy everything, then paste it into ChatGPT, Claude or Cursor and let it apply the edits.

Comments arrive in Slack and Telegram

Every new comment and reply lands in a chat your team already reads, with the page, the quoted text, the message and a link back to the thread. Each project can have its own Telegram bot, its own Slack channel, or both.

Telegram. Paste a token from @BotFather and press Start. Add the bot to a group and the whole team sees it.

Slack. One link creates a ready-made Slack app. Pick a channel and paste its webhook URL. The panel posts a hello and keeps the URL only if Slack accepts it.

The Start link carries a code only your project knows, so a stranger who finds the bot cannot become the recipient. Delivery is fire-and-forget: a slow or blocked bot or webhook never delays a comment.

A guest on your page

Every conflict between the widget's clarity and your page's readability resolves toward your page.

  • It never rewrites your markup.Highlights paint over text ranges with the CSS Custom Highlight API, so copy-paste and find-in-page keep working.
  • It never asks for attention.With zero threads the launcher is a small neutral marker. It earns a count once something is open.
  • It never borrows your styles.The widget lives in a shadow root and sizes itself in pixels, so a host with a 10px root font cannot shrink it.
  • Amber means an open thread.Nothing else, anywhere. Resolved is the absence of amber plus a word, so color never carries meaning alone. 1 open 2 overlap 3 or more

Painted highlights need Chrome 105, Safari 17.2 or Firefox 140. Below that the widget still loads and every thread is still reachable from the sidebar.

Self-host with one Node process and one SQLite file

The server runs TypeScript directly on Node 22.18 or newer. No transpiler, no native modules, no database server. Put it behind anything that terminates TLS, set TC_PUBLIC_ORIGIN to its public address, and it is done.

The source is on GitHub, with deploy notes for a VPS behind a Cloudflare Tunnel.

Run it yourself
git clone https://github.com/parhumm/teammate-comment
cd teammate-comment
npm install
npm run build:widget
npm run start   # panel + API on http://localhost:8787

Common questions

What is Teammate Comment?
A comment layer for web pages. Add one script tag and anyone who opens the page can select text, leave a comment and reply, like comments in a Google Doc. Only the site owner resolves and deletes. Teams use it to review websites, blog drafts, docs and HTML reports.
Do reviewers need an account?
No. Commenters never sign up: the widget asks for a name once, plus an optional email only the site owner sees, and keeps both on their device. Only the site owner has an account.
Which sites and platforms does it work with?
Any page where you can add a script tag before </body>: WordPress, Webflow, Ghost, Squarespace, Shopify themes, static site generators and hand-written HTML. A project covers its domain and every subdomain, so staging.acme.com works under acme.com.
Can I comment on an HTML report?
Yes, once the report is served from a URL on your project's domain, such as reports.acme.com/q3.html. A file opened straight from disk has no domain, so the widget does not load there; serve it from localhost, which a project can name as its domain, or upload it.
Can my blog's readers use it as a comment section?
Not yet. It is built for review with people you trust: anyone who can open the page can post, and comments appear at once with no approval step. Only you can delete them. Use it on drafts, staging and pages you share with your team or clients.
Will it change or slow down my page?
It never rewrites your markup or borrows your styles: highlights are painted with the CSS Custom Highlight API, and the widget lives in a shadow root. The script is under 20 KB gzipped.
Where do I see every comment?
In your dashboard. It lists every thread per project, filtered by page and by open or resolved. Reply, resolve, reopen, edit, delete or copy as Markdown from there, or open the page signed in as the owner.
How do I send the comments to ChatGPT or Claude?
Open the sidebar and press Copy all. Threads come out as Markdown with the page URL, the element, the quoted text and every reply, ready to paste into ChatGPT, Claude or Cursor.
Can I host it myself?
Yes. The source is on GitHub under the MIT license, and the server is one Node process with one SQLite file.
